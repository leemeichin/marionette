# TypeScript/SWI ↔ Racket parity lab

This directory freezes externally visible behaviour before the Racket port or
language imports change either implementation. It is the migration boundary
described by issue #33:

- structured diagnostic codes, severities, and source locations;
- semantic trajectory JSON and graph hashes;
- walker state, frontier effects, audit entries, and refusal codes.

It deliberately does not compare TypeScript classes, Prolog terms, Racklog
relations, prose diagnostics, or internal AST representations.

## Packet

[`reference.json`](reference.json) freezes per-case and whole-packet SHA-256
digests generated by today's TypeScript/SWI implementation from existing
checked-in fixtures. The unhashed packet printed by `parity:capture` conforms
to [`packet.schema.json`](packet.schema.json) and contains:

- every graph conformance diagnostic fixture;
- normalized trajectories for the small and kitchen-sink plans;
- every versioned walker conformance script, including successful effects and
  refused operations.

Trajectory `source` and all legacy integer `line` fields are removed before
comparison because they are provenance rather than semantics. The semantic
hash remains and must match. Diagnostic locations remain because they are part
of the compiler contract.

The digest manifest keeps the PR small while still making any reference drift
a build failure. The timestamp is pinned to `2026-01-01T00:00:00.000Z`; no
generated-at value or machine path is present.

## Commands

Check that TypeScript/SWI still produces the frozen reference:

```console
npm run parity:reference
```

Print a freshly captured reference packet:

```console
npm run parity:capture
```

Compare a Racket-produced packet:

```console
npm run parity:check -- --candidate path/to/racket-parity.json
```

Until the human implementation gate opens, no candidate exists. The compare
command exits with code 2 and explains exactly which file is missing. Once the
Racket slice can emit the packet, any semantic mismatch exits with code 1 and
reports the first JSON path that differs.

## Candidate contract

The Racket harness may consume these source fixtures directly or use its own
driver, but its output is one JSON packet matching the schema. Candidate
generation must:

1. use the checked-in `.mar` and walk-script paths named in the packet;
2. preserve array order where authoring or operation order is observable;
3. sort diagnostic findings by `code`, then line;
4. pin operation time to the vector's base time plus each `elapsed` value;
5. include state after refusals so atomicity remains observable;
6. normalize trajectories by removing `source` and every object key named
   `line`, while retaining `hash`.

The first vertical slice can emit only the cases it implements to aid
development, but it cannot claim parity until the complete packet compares.
