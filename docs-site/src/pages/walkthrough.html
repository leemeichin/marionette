walkthrough

One plan, end to end: author it, fail the build, fix it, compile it, review it, hand it to an agent, gate it as a human, finish it — then edit it mid-flight and reconcile. Every terminal below replays a captured session of the real CLI; nothing is mocked.

1 · Write down what you actually mean

The project: revamp a checkout flow. The intent: iterate behind a feature flag until conversion moves, let a human decide when it ships, and have an answer for "what if it never converts?". A first draft usually looks like this — and has the classic two bugs: the iteration loop isn't declared, and the rollout phase quietly goes nowhere.

2 · The compiler reads it more carefully than you do

Both errors are the plan lying about itself. The undeclared cycle asks: did you mean to iterate here, and what bounds it? The dead end asks: then what? Marionette refuses to hand an agent a plan that cannot answer.

3 · Fix by deciding, not by appeasing

The fix forces real decisions: the loop gets a budget (attempts < 5) and a declared ~loop~ mark, the budget's exhaustion gets an escalation path (rethink, gated @human), and rollout flows to END.

4 · Compile to the contract

The trajectory JSON is the machine contract an executor ingests. Its content hash is what traversal state binds to — you'll see it again.

5 · Review without reading the DSL

Reviewers don't have to parse syntax: summarize produces a plain-language walkthrough with every human checkpoint called out, and render emits a Mermaid graph (human gates flagged ✋, loops ↻).

6 · Hand it to the walker

state init creates checkout.state.json next to the plan, bound to the compiled hash. Entering the first phase applies its mutation (attempts ticks to 1) and shows the frontier: what can happen next, and what's blocked and why.

An executing agent doesn't look at the state file — it asks for the brief, the work packet: current phase prose (the author's instruction), live variables, the frontier with reasons, and the exact protocol for recording an outcome.

7 · The agent tries the gate — and is refused

Choice [0] is marked @human. The refusal is a machine-coded error (human-checkpoint, exit 1), and refused operations don't touch state. Autonomy boundaries here are walker guarantees, not prompt suggestions.

So the agent does what it may: takes the iteration edge, with its rationale logged. Re-entering the phase ticks the counter — the loop budget is being spent, visibly.

8 · The human takes the gate

The cohort numbers come in. The same command, a human actor, an honest rationale — the decision and its evidence are now part of the plan's permanent log.

9 · Edit a live plan, get caught, reconcile

Rewind to mid-walk (the agent parked at build_checkout, two attempts in) and suppose you edit the plan — say, adding a postmortem phase after rollout. Any semantic edit changes the content hash, and every walk command refuses with exit code 3 rather than misapply history to a graph it wasn't recorded against:

state rebind is the sanctioned path: it migrates the state onto the edited plan, keeps the decision log, and reports exactly what changed in the crossing.

And that's the whole loop

Author → compile → review → traverse → escalate → decide → complete, with drift detection guarding the whole way. To run this yourself: getting-started. To see what the executor consumes programmatically: execution.
