## Walkthrough

### greybox_prototype (start)
Greybox the core loop prototype: playable mechanics, placeholder art, nothing else.
Done when the loop can be played end to end in a weekly playtest build.
- on entry: `playtest_weeks = 0`
- **Core loop playable in greybox** → core_loop_iteration (repeatable)

### core_loop_iteration
Weekly playtest and iteration on the core loop.
Each week we playtest, read the room, and adjust; the creative director alone decides when it is actually fun.
- on entry: `playtest_weeks += 1`
- **Creative director calls it fun** → production_art_audio (**requires a human decision**; repeatable)
- **Not fun yet, iterate another week** → core_loop_iteration (only if `playtest_weeks < 8`; loops back; repeatable)
- **Eight weeks in, still not fun** → scope_change_pitch (only if `playtest_weeks >= 8`; repeatable)

### scope_change_pitch
Pitch the publisher a scope change instead of grinding on a loop that is not landing.
Done when the publisher gives a clear yes or no on the revised scope.
- **Publisher approves the new scope** → greybox_prototype (**requires a human decision**; loops back; repeatable)
- **Publisher declines, proceed with the best current loop** → production_art_audio (**requires a human decision**; repeatable)

### production_art_audio
Production art and audio for the vertical slice, replacing greybox assets.
Done when every asset in the slice is production quality.
- **Slice content complete** → polish_pass

### polish_pass
Polish pass across the slice: feel, transitions, bugs, performance.
Done when the slice is presentable to fresh internal players.
- **Polish bar met, start the gauntlet** → playtest_gauntlet (repeatable)

### playtest_gauntlet
Run one internal playtest session and measure the positivity score.
The submission bar is three consecutive sessions above 80 percent positive.
- **Session above 80 percent positive** → gauntlet_streak (repeatable)
- **Session at or below 80 percent positive** → gauntlet_reset (repeatable)

### gauntlet_streak
Record the positive session and check the streak.
- on entry: `positive_streak += 1`
- **Three consecutive wins, submit the slice** → submit_milestone (only if `positive_streak >= 3`; repeatable)
- **Streak alive, run the next session** → playtest_gauntlet (only if `positive_streak < 3`; loops back; repeatable)

### gauntlet_reset
A session missed the bar, so the streak resets to zero.
Fold the session feedback into the slice before running again.
- on entry: `positive_streak = 0`
- **Fold feedback into another polish round** → polish_pass (loops back; repeatable)
- **Gauntlet is not converging, leadership decides to submit as-is** → submit_milestone (**requires a human decision**; repeatable)

### submit_milestone
Package and submit the vertical slice milestone to the publisher.
- otherwise → publisher_review

### publisher_review
The publisher reviews the milestone against the contract.
Outcomes: pass, notes, or hard fail.
- **Pass, funding continues** → END (**requires a human decision**; repeatable)
- **Notes, one rework round granted** → rework (only if `rework_rounds < 1`; **requires a human decision**; repeatable)
- **Hard fail, cure period triggered** → cure_period (**requires a human decision**; repeatable)

### rework
Address the publisher's notes on the slice.
Done when every note is resolved or explicitly answered.
- on entry: `rework_rounds += 1`
- **Resubmit the revised slice** → publisher_review (loops back; repeatable)

### cure_period
The contract's cure period: do-or-die.
Leadership decides whether to spend our own runway fixing the slice or negotiate an exit.
- **Spend our runway to fix it** → rework (**requires a human decision**; repeatable)
- **Negotiate an exit with the publisher** → END (**requires a human decision**; repeatable)
