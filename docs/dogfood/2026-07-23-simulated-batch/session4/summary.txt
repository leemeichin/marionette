## Walkthrough

### build_mvp (start)
Build the MVP: the smallest version of the app worth putting in testers' hands.
Done when the core flows work end to end on a real device.
- **MVP is ready for testers** → closed_beta (repeatable)

### closed_beta
Closed beta via TestFlight: ship a build, collect feedback and crash reports, fix, repeat.
Done when the crash-free rate is above 99.5%.
- on entry: `beta_cycles += 1`
- **Crash-free rate is above 99.5%** → app_store_submission (repeatable)
- **Iterate on beta feedback** → closed_beta (only if `beta_cycles < 4`; loops back; repeatable)
- **Four cycles and still below target** → architecture_review (only if `beta_cycles >= 4`; **requires a human decision**; repeatable)

### architecture_review
The hard conversation: is the app architecture actually sound, or are we polishing something structurally broken?
- **Architecture is sound, keep working the beta** → closed_beta (**requires a human decision**; loops back; repeatable)
- **Architecture needs rework, rebuild the app** → build_mvp (**requires a human decision**; loops back; repeatable)
- **Not worth saving, stop here** → END (**requires a human decision**)

### app_store_submission
Submit to the App Store for review. Rejections are expected: read the feedback, fix, resubmit.
- on entry: `submissions += 1`
- **Apple approved the app** → launch_scheduling (repeatable)
- **Rejected, fix and resubmit** → app_store_submission (only if `submissions < 3`; loops back; repeatable)
- **Rejected three times, something fundamental is wrong** → rejection_escalation (only if `submissions >= 3`; **requires a human decision**; repeatable)

### rejection_escalation
Three App Store rejections means the problem is not cosmetic. Escalated to the project owner to decide the path forward.
- **Address the fundamental issue and rebuild** → build_mvp (**requires a human decision**; loops back; repeatable)
- **Shelve the launch** → END (**requires a human decision**)

### launch_scheduling
The app is approved. Marketing picks the actual launch date; that is their call, not engineering's.
- **Marketing confirms the launch date, go live** → launch_monitoring (**requires a human decision**; repeatable)

### launch_monitoring
The app is live. Monitor crash rates, reviews, and support channels closely for one week.
- **Serious incident, pull the app from the store** → closed_beta (**requires a human decision**; loops back; repeatable)
- **First week is clean** → maintenance_handover

### maintenance_handover
Hand the app over to the maintenance team: docs, dashboards, on-call. Project complete.
- otherwise → END
